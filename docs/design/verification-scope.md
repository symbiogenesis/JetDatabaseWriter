# Critical production behavior inventory

This inventory defines the production scope of the formal-verification workstream. Each ID includes its alternate, refusal, failure and retry paths. Listing a behavior does not establish its proof, native-format completeness or platform qualification. The [evidence map](verification-evidence-map.md) records those separate evidence levels against the same IDs. The [formal boundary](formal-verification.md) describes existing theorems; [PLAN.md](../../PLAN.md) retains unfinished implementation and acceptance work.

Priorities order work rather than exclude requirements. A shared-helper proof does not close its callers, and a successful path does not close a fallback. Newly discovered paths must join this inventory before a coverage claim expands. Review this scope with the source-domain classification below and the [continuing review policy](proof-trust-review.md).

## Required properties and environmental scope

Each behavior requires bounds before allocation/slicing/narrowing, exact identity and ownership checks, unrelated-content preservation, honest error/cancellation reporting and correct resource release. Mutations must prepare and validate before effects, retain evidence on uncertain outcomes and avoid reclaiming reachable or potentially referenced storage. Refusal must preserve the promised source/evidence state; it cannot replace support for valid input.

Progress is separate: finite valid supported inputs within explicit budgets must complete under eventually successful I/O, exclusive access where required and fair cooperating-client scheduling. Reads terminate or observe cancellation. Mutations and recovery need reachable successful completion paths. Infinite interruptions, permanent I/O failures or clients that never release locks do not imply eventual success. Current abstract progress proofs do not prove every handwritten production loop or deadlock freedom.

Native scope includes recognized Jet3 `.mdb` (2,048-byte pages), Jet4 `.mdb` and ACE `.accdb` (4,096-byte pages), with the variants implemented by the named paths. Recognition does not imply complete feature coverage. Pre-Jet3, unknown descriptors/collations/providers and opaque references retain E1/E2/F3/F8/F9/S1/S3/S9 requirements: safe refusal/preservation is in scope even when interpretation/writing is unsupported. Microsoft-authored/native-accepted observations, synthetic malformed inputs and library round trips are distinct evidence.

Recovery formats are library sidecars, not native Access logs. Recovery operates on raw bytes, including encrypted images; page codecs and format semantics have separate contracts. Native Jet3/Jet4 RC4 and implemented ACE Standard/Agile forms do not establish third-party provider or Office package support. Native Access does not replay this library's sidecars.

Execution scope covers shipped `netstandard2.1` and `net10.0` assets, CI's .NET 10/.NET 11 execution and Windows/Linux/macOS paths. The following remain explicitly qualified contracts:

| Boundary | Alternatives and required qualification |
|---|---|
| Storage effects | Short reads, EOF, throwing reads, full/partial failed writes, length changes, successful/failed flushes, disposal and older queued I/O. Exact bytes-and-length fencing and crash quiescence are assumptions. Pre-marker buffered zero exposure remains V3/V7. |
| Interruption | Process failure/repeated replay differs from power loss, media corruption or adversarial namespace edits. Content flush does not persist directory entries. E4/F6/I15/V7 retain OS/filesystem/device and physical interruption qualification. |
| Coordination | Canonical paths, native/receipt/intent/source leases and exclusive cooperating clients. macOS disables BCL byte-range locking. Windows/Linux evidence does not qualify macOS, SMB, alias paths, noncooperating Access or hostile namespace changes. |
| Caller streams | Production selects persistent recovery for supported `FileStream` paths. Other seekable streams/memory stores/temporary undo spill provide live rollback, without persistent-adapter guarantees (I15). Caller-owned outputs/callbacks require separate ownership/resource contracts. |
| Memory | Bound arrays, sets/dictionaries, fixed headers/scratch, caches and private output assembly together. Distinguish shared-pool capacity, runtime/GC overhead and caller-owned output. A per-page/value limit does not bound a complete public scan. |
| Cancellation/failure | Honor documented read/preparation cancellation. Mandatory commit/replay must finish or retain its decision rather than perform unsafe partial rollback. Preserve both primary and undo/cleanup failures. |

See the [storage contract](recovery-storage-contract.md), [caller-stream contract](caller-stream-recovery.md), [lock ordering](concurrency-and-lock-ordering.md) and [multi-process ownership](multi-process-ownership.md).

The scaffold executable, FormatProbe, test support/tests, benchmark harnesses, repository scripts and CI are outside shipped runtime theorem scope. They remain evidence/trust inputs: scaffold-generated consumers require target/trimming/AOT checks; probes/DAO supply provenance/native observations; verifier/compiler/projection/pin/gate tooling requires trust review. Exclusion cannot turn failed harnesses, skipped DAO cases or broken benchmarks into successful evidence.

Deferred pure query/expression/coercion/presentation proofs retain I9/R4/compatibility requirements. Unknown providers/forms and platform qualification retain their F/E/S/I items. Classification or proof-scope revision does not close independent functionality/safety acceptance obligations.
