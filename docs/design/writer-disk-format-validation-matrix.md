# Writer Disk-Format Validation Matrix

**Status:** Updated after complex/LVAL DAO validation, 2026-05-21.

This matrix is the single cross-reference for writer-emitted disk-format features and their strongest current validation level. Use it when updating design notes that mention Access Compact and Repair, DAO compatibility, or manual Access validation.

Validation levels, from weakest to strongest:

- **Reader round-trip**: the writer output is reopened through JetDatabaseWriter's reader and assertions cover schema/data/index metadata.
- **DAO OpenRecordset**: a bitness-matched Windows PowerShell host drives `DAO.DBEngine.120` against writer output and materializes recordsets or DAO index seeks.
- **DAO CompactDatabase**: DAO compacts the writer output, then JetDatabaseWriter reopens the compacted file and verifies schema/data/relationships/passwords as applicable.
- **Manual Access verified**: a human opened the file in Microsoft Access UI, ran Compact and Repair, and verified the result. This is a supplemental signal, not a replacement for automated DAO tests.

## Policy

- Prefer Access-authored fixtures such as Northwind for DAO compact tests. A writer-created fresh database is useful for unit coverage, but it makes catalog bootstrap output part of the trusted base.
- `CompactDatabase` exit code 0 is not enough. Reopen the compacted output and assert the feature that motivated the test.
- When a design note says "Microsoft Access compact-and-repair validation is pending," update it to name the exact matrix row that is pending or covered.
- Keep manual Access UI validation notes as secondary evidence. If the scenario can run through DAO on an Access-equipped host, add or extend an automated DAO test.
