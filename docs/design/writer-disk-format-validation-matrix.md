# Writer Disk-Format Validation Matrix

**Status:** Reviewed after fresh ACCDB bootstrap DAO validation and automated-vs-manual validation cleanup, 2026-05-22.

This matrix is the single cross-reference for writer-emitted disk-format features, their strongest automated validation level, and the remaining evidence gaps. Use it when updating design notes that mention Access Compact and Repair, DAO compatibility, or manual Access validation.

Automated validation levels, from weakest to strongest:

- **Reader round-trip**: the writer output is reopened through JetDatabaseWriter's reader and assertions cover schema/data/index metadata.
- **DAO OpenRecordset**: a bitness-matched Windows PowerShell host drives `DAO.DBEngine.120` against writer output and materializes recordsets or DAO index seeks.
- **DAO CompactDatabase**: DAO compacts the writer output, then JetDatabaseWriter reopens the compacted file and verifies schema/data/relationships/passwords as applicable.

Manual Access UI verification is separate from the automated ladder: a human opened the file in Microsoft Access, ran Compact and Repair, and verified the result. Keep that evidence in the remaining-gap notes when it exists, but do not treat it as stronger than DAO automation. If a scenario can run through DAO on an Access-equipped host, add or extend an automated DAO test.

## Policy

- Prefer Access-authored fixtures such as Northwind for DAO compact tests that validate writer mutations. A writer-created fresh database is useful for bootstrap coverage, but it makes catalog scaffolding part of the trusted base.
- `CompactDatabase` exit code 0 is not enough. Reopen the compacted output and assert the feature that motivated the test.
- When a design note says "Microsoft Access compact-and-repair validation is pending," update it to name the exact matrix row that is pending or covered; do not leave blanket validation warnings behind.
- Keep manual Access UI validation notes as secondary evidence. If the scenario can run through DAO on an Access-equipped host, add or extend an automated DAO test instead of relying on the manual note.
