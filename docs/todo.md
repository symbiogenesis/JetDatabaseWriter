# To do

Open work toward reading, preserving and writing every real Microsoft JET and ACE database format and resisting malicious databases. A file's provenance or age is not a reason to reject it. Compatibility means Microsoft-produced files and documented engine behavior; this library has never shipped, so its old APIs, invented encryption formats and damaged output create no compatibility obligation. Remove obsolete implementations instead of adding shims or repair APIs for them.

Keep only open work here. A fixing commit removes the completed item (or narrows it to the remaining gap), updates affected design notes, and supplies regression evidence. Do not delete a compatibility requirement merely because safe rejection has been implemented. Distinguish Microsoft-authored fixtures, independent implementation agreement, library round trips, and unverified hypotheses.

## F — Real formats and encryption

- **F2 — Verify fixed-length Text across code pages and preserved schemas.** DAO establishes space padding for short fields; over-width assignments are deliberately refused rather than silently truncated. Extend native evidence beyond Jet4/ACE ASCII to Jet3, multibyte code pages, embedded NULs and malformed unassigned fields (I6). Preserve descriptor widths and storage flags through every schema edit.
- **F3 — Complete native JET/ACE encryption and password maintenance.** Native JET4 RC4 and password-only reads now have DAO-produced fixtures, and existing encrypted pages retain their key/password during updates. Implement the system-security metadata changes required for encrypt/decrypt/password changes, currently refused before mutation. Complete actual flat ACE RC4 CryptoAPI and ECMA-376 Standard providers from Microsoft-produced files and primary specifications; extend Agile beyond the native AES256-CBC/SHA512 fixture. JET3 RC4 now has a pinned upstream encrypted fixture; verify native Access97 password, mutation and compact behavior with a compatible engine. Office CFB packages and library round trips alone do not prove Access database compatibility.
- **F4 — Verify page-based Access-native Agile mutations.** A native provider now unlocks once and uses the normal page codec/pager while preserving page 0. Extend the successful native AES256-CBC/SHA512 DML/DDL/rollback, shrink/scrub and DAO write/compact cases on both targets to other supported algorithms. Extend malformed-parameter, bounded-open and physical shrink fault-sweep coverage; scrub write/torn-write/flush rollback tests establish library ciphertext restoration, not native crash semantics.
- **F6 — Stream encryption maintenance and avoid plaintext creation.** Re-encrypt flat formats page by page with atomic replacement; create encrypted databases directly. Bound memory, honor cancellation, preserve the original on failure, and handle stale temporary files without deleting another active operation's file. Verify Unix directory durability and netstandard replacement behavior; document actual guarantees. Use a coherent file-maintenance API without preserving old AccessWriter statics merely for compatibility.
- **F7 — Match Jet3 table-definition bytes.** Check 0x80 index flags, `VC` page signature/continuations, index trailers, statistics slots, descriptor bytes 7–12, and unknown page-0 bytes 0x600–0x7FF against Access 97. Preserve unknown bytes; change bootstrap hashes only with byte-level evidence. Verify Currency and decimal declarations/keys against Access 97; avoid silently narrowing a declaration Currency cannot represent.
- **F8 — Match row and long-value layout.** Verify reserved fixed-field space, fixed-only Jet3 trailers, real Jet3 jump-table boundaries, and Access record limits near 2,000/4,000. Current capacity tests prove only library round trips at 2,036/4,080 bytes. Extend native LVAL token and packing coverage beyond the verified end packing and 64-byte inline limit; verify compressed calculated Memo variants consistently for inline and spilled values. Include DAO read/compact and no-allocation-on-refusal checks.
- **F9 — Support actual collations and code pages.** Inventory supported/unsupported real database and per-column sort orders; expose explicit choices and preserve them during schema edits. Verify General 97, General Legacy and General keys, long keys, locale comparisons and uniqueness against Microsoft evidence. Repairing keys written by an old library build is not required.
- **F10 — Bootstrap standard Jet3 system objects.** New Jet3 databases lack the system rows/tables needed by `CreateRelationshipAsync`. Create the native catalog structures, preserve ownership/permissions and other metadata, and prove an Access97-compatible engine can open, enforce relationships and compact newly created databases.
- **F11 — Validate attachments and complex descriptor variants.** Obtain an Access-authored extensionless attachment; verify raw/compressed wrappers, extension lengths, empty payloads and extraction after compact. Check multi-value Decimal flags/misc bytes, calculated types, append-only metadata on real fixtures, including additional complex reference and counter variants. Compression must obey S2 resource limits.
- **F12 — Centralize verified format facts.** Consolidate per-type sizes/mappings/flags and per-format header/text/null/row layout facts under JetFormat and a type table. Characterize all 256 type codes without treating unknown codes as valid defaults. ## S — Hostile-file parsing and schema preservation

- **S1 — Complete cross-surface bounds and traversal auditing.** Audit remaining header/data/index/usage-map/complex/catalog paths before allocation, slicing or arithmetic; use long offsets and checked bounds. Per-definition TDEF limits do not bound a catalog containing many individually valid definitions, and CFB metadata/aliased sector chains can amplify total work independently of extracted-stream bytes. Add aggregate schema/traversal budgets and shared-chain ownership checks. Reproduce truncation, contradictory counts, cyclic pointers and partial reads across public APIs. Native LVAL descriptors carry 30-bit lengths; verify large real values beyond the default 16 MiB read budget and current writer emission limit. Cancellation must terminate long traversals.
- **S2 — Bound aggregate decompression and cryptographic work.** Per-value attachment, CFB, XML and PBKDF limits do not bound scans over many attachments or encrypted linked sources. Add aggregate operation budgets and cancellation within synchronous inflation/password work, while preserving supported large real files through explicit caller limits. Reproduce many individually valid high-cost values and invalid algorithm/parameter combinations; extend native provider evidence separately under F3. Package HMAC regressions do not establish authentication for native page encryption or descriptors without integrity metadata.
- **S3 - Complete the public decode-fault policy.** Extend the shared value failure policy through other fixed-slot types and bounds and remaining long-value diagnostic paths across typed, string, POCO and calculated reads. Preserve unassigned raw values during writes and refuse mutation that would erase unreadable assigned content. Cover every public surface and propagate real I/O errors.
- **S4 — Complete property mutation refusal and native verification.** Extend malformed-chain refusal through all remaining property-edit/rewrite entry points and write modes. - **S6 — Complete linked-source access boundaries.** Bind authorization to actual opened handles to close symlink/alias races and examine physical identity and hard links. - **S8 — Verify complex schema edits with DAO.** Preserve internal reference indexes and generate them for new complex columns; confirm DAO open/compact after the complete rewrite, including multi-page TDEFs. - **S11 — Make failures and diagnostics usable.** Give deliberate corruption, encryption, unsupported-format, size and state failures structured codes/context; preserve real I/O exceptions. ## I — Indexes, storage, APIs and validation

- **I2 — Maintain and reclaim index trees correctly.** Replace remaining whole-tree rebuild/splice paths with verified B-tree insert/delete/split/merge. Preserve opaque real pages until their representation is understood (including Jet3 prefix length). Reclaim replaced trees, dropped FK leaves and empty pages without freeing shared/reachable pages; renumber cross-TDEF references when compacting descriptor slots. Reclaim original pages still named by preserved native Jet3 index maps once map mutation is verified. Validate key/page/row ordering, ownership, usage maps, root growth and DAO compact. Retain the FK rebuild fallback until interoperability proves it can be removed.
- **I3 — Maintain all real usage maps.** Implement Jet3 table/index maps and column-owned/free LVAL maps. The writer omits LVAL map entries; data free-space maps remove pages only when no nonempty row or additional row slot can fit. Verify Access thresholds and deletion/reuse behavior, including Jet3. Validate INLINE-to-REFERENCE growth for owned/index/free maps against Access; allocate surgical splits through PageAllocator and undo failed reservations.
- **I5 — Unify mutation validation and rollback.** Use one pipeline for row, cascade, complex, catalog and system writes; prepare/plan/validate before applying and maintain each affected index once per batch. Restore counters, allocator hints, catalog generations and caches on every rollback/failure. Extend byte-level write/flush/truncate fault sweeps to initial creation, physical shrinking and native encryption maintenance, which have separate lifecycles.
- **I6 — Update rows without lossy full rewrites.** Preserve raw unassigned fields/LVAL chains, update in place where the format allows, relocate overflow safely, and seek update/delete targets and unique keys. Non-key changes should avoid index writes; support swapped batch keys atomically. Bound memory for schema rewrites and investigate in-place DDL after preservation is proven.
- **I7 — Bound page/cache memory and establish ownership.** Add leases/pins and correct copy-on-write where beneficial; never recycle pinned/transaction pages. Unify source interfaces and invalidation, remove redundant caches/adapters only with concurrency/abandoned-scan tests and paired benchmarks. Pin counts return to zero after seeks, cancellation, LVAL traversal and concurrent scans with tiny caches.
- **I8 - Compose reads and cache catalog work.** Cache verified resolved table/index/complex descriptors, read only the selected LvProp, and invalidate writer caches on every relevant change. Use a shared scan primitive. Linked Access indexes/complex reads resolve to their approved source; text links expose no indexes; ODBC execution stays explicit. Repeated metadata/count/miss/seek operations should avoid disk I/O after warmup.
- **I9 — Cache query plans and push projections safely.** Parameterize captured values without freezing mutable closures, bound shape/materializer caches, and decode only referenced columns. Use correct rounded seek bounds for integral/Currency/Decimal/Single comparisons, and ordered indexes for Min/Max when semantics permit. Profile collection Include before changing its full-child materialization. Test concurrency, eviction and changing captures.
- **I11 — Measure page I/O on representative systems.** Investigate duplicate reader header reads, overlapped writer-handle cost, gated Disabled-mode concurrent scans, complex-column read-ahead, and the unexplained cold SequentialScan/first-row handoff regressions. Test Windows x64/Arm64, Linux/macOS, local disk and SMB with cancellation behavior; retain measured changes only.
- **I12 — Re-establish performance acceptance with controls.** Hosted paired typed-MEMO regressions were 5.7–13.3%, while an identical-revision control differed by 6–8%; the former 2% target is unresolved. Use repeated swapped-order/control measurements on a controlled runner. This is an acceptance requirement for relevant performance changes, not a blocker for security/correctness fixes. Preserve the evidence in read-performance-bottlenecks.md.
- **I13 — Scale relational/attachment benchmarks after write fixes.** The fixtures remain 10,000 orders and 150 attachment rows because relationship/flat-table indexes rebuild per item. Grow versioned fixtures after I2/I5, measure bounded per-item I/O and allocations, and run paired baseline/head benchmarks on GitHub Actions. Treat NA means or broken runs as failures, not evidence.
- **I14 — Complete the public capability documentation audit.** Audit remaining API comments and design notes against the corpus, structured decode failures, linked-source permissions, encryption provenance and target-framework differences. Keep documentation synchronized with native evidence as remaining schema, application-object preservation, crash recovery and format requirements land. Do not advertise full JET/ACE support or malicious-input resistance as established while required evidence is missing.
- **I15 — Establish power-loss and custom-stream recovery guarantees.** File recovery flushes journal and database contents, but journal directory-entry persistence across power loss is not established. Add and verify the required OS/filesystem ordering with fault sweeps that include journal creation, commit decisions and cleanup; reproduce interrupted recovery and committed-journal cleanup across supported platforms. Caller streams have no portable persistent identity or reopen protocol: design an explicit journal-stream contract and verify caller-enforced exclusive access before promising recovery. Access does not replay this library's sidecar, so native opens after a crash must follow library recovery.
- **I16 — Reduce crash-journal snapshot cost.** Every file transaction currently copies the original database into a bounded-buffer journal before its first write; a one-row autocommit in a large database therefore copies the whole file. Develop a selective before-image protocol that preserves full conflict detection, torn-write validation and idempotent recovery, then compare grouped and individual transactions with hosted paired benchmarks.
