# To do

Open work toward reading, preserving and writing every real Microsoft JET and ACE database format and resisting malicious databases. A file's provenance or age is not a reason to reject it. Compatibility means Microsoft-produced files and documented engine behavior; this library has never shipped, so its old APIs, invented encryption formats and damaged output create no compatibility obligation. Remove obsolete implementations instead of adding shims or repair APIs for them.

Keep only open work here. A fixing commit removes the completed item (or narrows it to the remaining gap), updates affected design notes, and supplies regression evidence. Do not delete a compatibility requirement merely because safe rejection has been implemented. Distinguish Microsoft-authored fixtures, independent implementation agreement, library round trips, and unverified hypotheses.

## Acceptance and parallel execution

- **E1 — Establish the real-format corpus.** Inventory JET generations, ACE generations and feature variants, including formats predating Jet3, Access 97/2000/2003/2007 and later engines, password protection, encryption, code pages, collations, replicated databases, system objects and complex values. Record provenance, producing engine/version, hashes and expected data. Investigate unsupported generations from actual files rather than interpreting them as Jet3 or Jet4. Expand `writer-disk-format-validation-matrix.md`; no blanket claim of complete support until the matrix has evidence.
- **E2 — Run Microsoft interoperability checks.** Run targeted DAO-guarded tests locally on an Access-equipped host using locally built or matching CI-built binaries, including the engine support needed for Access 97, and check open, read, insert, update, delete and Compact & Repair. Full test suites remain CI-only. DAO120 runs through an x64 host and refuses Access97; activated x86 DAO3.6 provides native Jet3 encryption evidence. Other Access97 feature variants still need their own checks. Expand the successful guarded cases recorded in the validation matrix to the unverified feature variants. Missing hosts or fixtures remain explicit external dependencies; skipped DAO tests do not prove interoperability.
- **E4 — Complete operating-system durability and coordination evidence.** Establish a fully managed directory-durability or recovery protocol on Windows/Linux/macOS (F6); flushing replacement contents alone does not persist the renamed directory entry. Verify macOS process coordination beyond the deliberately disabled BCL byte-range-lock option. A process killed after journal cleanup can leave a lockfile that ordinary writer open refuses; establish safe stale-lock ownership before automatic cleanup.
- **E5 — Validate the first release workflow.** Exercise artifact handoff, package naming and publication recovery when a release is explicitly authorized. Do not add a previous-package compatibility baseline before a release exists; current targets must still expose consistent APIs.

All items belong to a workstream; independent items may run immediately without waiting for unrelated performance refactors. Dependencies follow data ownership and correctness, not the former 17-stage schedule. Every agent, including reviewers, gets a dedicated worktree. Only the integrator changes shared instructions, this list, shared docs and final CI configuration. Agents report exact completed requirements and remaining evidence gaps; the integrator reviews and lands their work on main.

## R — Relationships and constraints

- **R4 — Complete Access expression semantics.** Verify CurrentUser against native and workgroup behavior; match native Null semantics for stale bracketed calculated qualifiers after table rename (repro: DAO retains `[T].[Price]`/`[T]![Price]`/`[T].Price` text, yields Null and refuses compact with error 3790; the writer currently refuses recalculation before mutation; plan R4, see the calculated-column notes), and support domain aggregates and Eval through bounded, non-executing interpretation. Carry VBA numeric Variant subtypes through arithmetic and subtype-sensitive functions; `CStr(1/3)` currently differs. Verify radix-literal acceptance in native Access expression contexts; Access Eval refuses `TypeName(&H10)` despite VBA literal typing. Check named date/time/number formats against the database locale, date arithmetic, three-valued/bitwise operators, `%`, time-only dates and rounding against Access. Represent and preserve native calculation errors independently of ordinary Null: DAO120 stores a 39-byte Byte error envelope with first UInt32 6 and payload length 0 for Boolean True and out-of-range numeric results; ordinary Null is a 23-byte zero envelope. Public reads currently conflate them, and writers refuse result overflow rather than persisting the native error envelope. Complete error-envelope read/write/update semantics against Microsoft-authored fixtures and extend context-specific function/conversion evidence. Never run VBA, macros, external commands or arbitrary CLR code to evaluate database content.
- **R8 — Support complex-item mutation and history.** Expose stable item IDs, remove/replace individual attachments and multi-value entries atomically, maintain flat-table indexes/counts, and verify typed parent-key matching against DAO across supported collations. Updating append-only Memo must write Access-compatible version history; version-history records must not be arbitrarily editable. Test DateTime, GUID, decimal, binary and MEMO parent keys and DAO compact/extraction.

## F — Real formats and encryption

- **F3 — Characterize third-party native encryption providers.** Legitimate extensible providers and non-AES Agile ciphers remain unsupported. Obtain actual native ACE descriptors, producing modules and documented provider contracts before implementing their key derivation and page transforms; Office package structures and synthetic round trips do not establish native compatibility.
- **F6 — Establish power-loss encryption replacement guarantees.** Managed file flushing does not persist the containing directory after replacement or backup cleanup. Investigate a managed recovery protocol and exercise power interruption around rename and cleanup on supported filesystems, including recovery when only staging/original copies remain. Do not treat injected exceptions or file-content flushes as directory-entry durability evidence.
- **F8 — Match row and long-value layout.** Verify reserved fixed-field space, fixed-only Jet3 trailers, real Jet3 jump-table boundaries, and Access record limits near 2,000/4,000. Current capacity tests prove only library round trips at 2,036/4,080 bytes. Extend native LVAL token and packing coverage beyond the verified end packing and 64-byte inline limit; verify compressed calculated Memo variants consistently for inline and spilled values. Include DAO read/compact and no-allocation-on-refusal checks.
- **F9 — Support actual collations and code pages.** Inventory supported/unsupported real database and per-column sort orders; expose explicit choices and preserve them during schema edits. Verify General 97, General Legacy and General keys, long keys, locale comparisons and uniqueness against Microsoft evidence. Repairing keys written by an old library build is not required.

## S — Hostile-file parsing and schema preservation

- **S1 — Complete cross-surface bounds and traversal auditing.** Audit remaining header/data/index/usage-map/complex/catalog paths before allocation, slicing or arithmetic; use long offsets and checked bounds. Recover remaining catalog identities when physical ownership and independent Id-index evidence are both damaged or unavailable, including moved-row ownership and missing or corrupt allocation hints; consistency refusal alone does not recover them. Complete aggregate traversal and collection-memory limits for the remaining public scans, including cache lifetime, collection overhead and fixed scratch/header storage; qualify runtime, shared-pool and caller-owned allocations separately. Complete root/directory size/count consistency checks. Reproduce truncation, contradictory counts, cyclic metadata pointers, and partial reads across public APIs. Native LVAL descriptors carry 30-bit lengths; verify large real values beyond the default 16 MiB read budget and current writer emission limit. Cancellation must terminate long traversals.
- **S3 - Complete the public decode-fault policy.** Audit remaining type-specific scalar validation beyond fixed-slot bounds and Complex reference IDs. Calculated Numeric nonpositive prefixes use an inferred width and empty mantissas still return `DBNull`; verify their null/zero/corruption semantics and compact-width representations against Microsoft-authored files. Audit remaining descriptor failures beyond inline declared-length validation, plus chain and calculated OLE/envelope failures across typed, string, POCO and calculated long-value reads. Strict reads need contextual corruption; explicitly lenient reads need a documented missing-value representation and diagnostic. Preserve unassigned raw values during writes and refuse mutation that would erase unreadable assigned content. Cover every public surface and propagate real I/O errors.
- **S4 — Verify remaining native property layouts.** Obtain Microsoft-authored or native-accepted multiple-name-pool LvProp layouts and establish their binding semantics before expanding write support. Repro: adding a second identical name pool to a DAO-created Jet4/ACE property blob causes DAO120 to omit the table ValidationRule and refuse insertion as corrupt before any writer edit. Verify native acceptance of repeated equivalent rule/text entries and empty-name table targets, which current regressions create synthetically. Verify preserved multiple-pool output and Jet3 property edits with a compatible native engine.
- **S7 — Preserve remaining unmodeled schema bytes during edits.** Use parsed TDEF/property models to retain unknown header/trailer and chunk bytes plus sort metadata during Add/Drop/Rename. Preserve standalone descending FK trees and distinct physical index identities when a generated rewrite changes their sort order or merges incompatible native descriptors; these edits currently refuse (plan S7). Cover surviving values/indexes/relationships and the absence of temporary tables on wider Microsoft-authored fixtures.
- **S9 - Preserve schema dependencies and application objects.** Rename/drop must handle table ValidationRule, lookup RowSource and saved-query dependencies with verified Access behavior, or refuse edits it cannot safely preserve. Verify native column dependency rewriting for Filter and OrderBy; rename/drop currently refuse a table with either nonempty property because these dependencies cannot be safely rewritten. Determine Name AutoCorrect semantics. Preserve forms/reports/macros/modules/query definitions, replication/security metadata and unknown system objects byte-for-byte when unrelated data is edited; do not execute embedded code.
- **S11 — Make failures and diagnostics usable.** Give deliberate corruption, encryption, unsupported-format, size and state failures structured codes/context; preserve real I/O exceptions. Remove message matching and exception-driven valid control flow. Audit diagnostic callback invocation under I/O/pager locks and reentrancy, and add optional EventSource counters. No old BCL base or message must be retained solely for compatibility with this unreleased library.

## I — Indexes, storage, APIs and validation

- **I2 — Maintain and reclaim index trees correctly.** Replace remaining whole-tree rebuild/splice paths with verified B-tree insert/delete/split/merge. Preserve opaque real pages until their representation is understood (including Jet3 prefix length). Reclaim replaced trees, dropped FK leaves and empty pages without freeing shared/reachable pages; renumber cross-TDEF references when compacting descriptor slots. Validate key/page/row ordering, ownership, usage maps, root growth and DAO compact. Retain the FK rebuild fallback until interoperability proves it can be removed.
- **I5 — Unify mutation validation and rollback.** Use one pipeline for row, cascade, complex, catalog and system writes; prepare/plan/validate before applying and maintain each affected index once per batch. Restore counters, allocator hints, catalog generations and caches on every rollback/failure. Extend byte-level write/flush/truncate fault sweeps to caller-stream creation and remaining native encryption conversion paths, which have separate lifecycles.
- **I6 — Update rows without lossy full rewrites.** Preserve raw unassigned fields/LVAL chains, update in place where the format allows, relocate overflow safely, and seek update/delete targets and unique keys. Non-key changes should avoid index writes; support swapped batch keys atomically. Bound memory for schema rewrites and investigate in-place DDL after preservation is proven.
- **I7 — Bound page/cache memory and establish ownership.** Add leases/pins and correct copy-on-write where beneficial; never recycle pinned/transaction pages. Unify source interfaces and invalidation, remove redundant caches/adapters only with concurrency/abandoned-scan tests and paired benchmarks. Pin counts return to zero after seeks, cancellation, LVAL traversal and concurrent scans with tiny caches.
- **I8 - Compose reads and cache catalog work.** Cache verified resolved table/index/complex descriptors, read only the selected LvProp, and invalidate writer caches on every relevant change. Use a shared scan primitive. Linked Access indexes/complex reads resolve to their approved source; text links expose no indexes; ODBC execution stays explicit. Repeated metadata/count/miss/seek operations should avoid disk I/O after warmup.
- **I9 — Cache query plans and push projections safely.** Parameterize captured values without freezing mutable closures, bound shape/materializer caches, and decode only referenced columns. Extend safe seek inference to rounded integral/Currency/Decimal/Single comparison bounds, and ordered indexes for Min/Max when semantics permit. Preserve operand evaluation order and short-circuit behavior when caching plans or expanding inference. Profile collection Include before changing its full-child materialization. Test concurrency, eviction and changing captures.
- **I11 — Measure page I/O on representative systems.** Investigate duplicate reader header reads, overlapped writer-handle cost, gated Disabled-mode concurrent scans, complex-column read-ahead, and the unexplained cold SequentialScan/first-row handoff regressions. Test Windows x64/Arm64, Linux/macOS, local disk and SMB with cancellation behavior; retain measured changes only.
- **I12 — Re-establish performance acceptance with controls.** Hosted paired typed-MEMO regressions were 5.7–13.3%, while an identical-revision control differed by 6–8%; the former 2% target is unresolved. Use repeated swapped-order/control measurements on a controlled runner. This is an acceptance requirement for relevant performance changes, not a blocker for security/correctness fixes. Preserve the evidence in read-performance-bottlenecks.md.
- **I13 — Scale relational/attachment benchmarks after write fixes.** The fixtures remain 10,000 orders and 150 attachment rows because relationship/flat-table indexes rebuild per item. Grow versioned fixtures after I2/I5, measure bounded per-item I/O and allocations, and run paired baseline/head benchmarks on GitHub Actions. Treat NA means or broken runs as failures, not evidence.
- **I15 — Establish power-loss and custom-stream recovery guarantees.** File recovery flushes journal and database contents, but journal directory-entry persistence across power loss is not established. Add and verify the required OS/filesystem ordering with fault sweeps that include journal creation, commit decisions and cleanup; exercise power interruption during recovery replay and committed-journal cleanup on supported filesystems. Caller streams have no portable persistent identity or reopen protocol: design an explicit journal-stream contract and verify caller-enforced exclusive access before promising recovery. Access does not replay this library's sidecar, so native opens after a crash must follow library recovery.
- **I16 — Reduce crash-journal snapshot cost.** Every file transaction currently copies the original database into a bounded-buffer journal before its first write; a one-row autocommit in a large database therefore copies the whole file. Develop a selective before-image protocol that preserves full conflict detection, torn-write validation and idempotent recovery, then compare grouped and individual transactions with hosted paired benchmarks.
- **I17 — Support Compact & Repair.** Implement managed compaction and as much safe repair as the real JET/ACE formats permit. Assemble bounded raw-field/LVAL discovery, private data packing, bookmark relocation, stored-key index staging and known cross-root ownership observations into a complete compact copy and result validation (I17.3/I17.4). Retarget LVAL, catalog, TDEF and map references while preserving pinned storage; a staged row with unchanged source LVAL pointers is not a compact database. Recover remaining catalog identities when both physical ownership and independent index evidence are unavailable or damaged; calculated-property hydration must also consume safely recovered catalog rows rather than only physical-owner scans (I17.1/I17.3). Rebuild reachable data, long values, indexes and usage maps into a separate validated database; reclaim unused space while preserving schema, relationships, complex-item identities, encryption, security, application objects and unknown metadata. Diagnose and recover independently readable content from damaged files without inventing lost values or silently dropping objects; report unrecoverable damage and every recovery decision. Bound memory and traversal, support cancellation, leave the source unchanged on refusal, and replace it only after validation with crash-safe recovery. Compare Microsoft-authored healthy and deliberately damaged Jet3/Jet4/ACE fixtures with native Compact & Repair, including DAO reopen/read/constraint checks and byte-preservation checks for unsupported features. Follow the [implementation and acceptance plan](design/compact-and-repair.md); its dependency table identifies the required portions of S1/S3/S7/S9, F8/F9, I2/I6, E1/E2/E4, F6 and I15 without blocking independent compact-copy work on unrelated tasks.
