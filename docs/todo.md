# To do

Open work toward reading, preserving and writing every real Microsoft JET and ACE database format and resisting malicious databases. A file's provenance or age is not a reason to reject it. Compatibility means Microsoft-produced files and documented engine behavior; this library has never shipped, so its old APIs, invented encryption formats and damaged output create no compatibility obligation. Remove obsolete implementations instead of adding shims or repair APIs for them.

Keep only open work here. A fixing commit removes the completed item (or narrows it to the remaining gap), updates affected design notes, and supplies regression evidence. Do not delete a compatibility requirement merely because safe rejection has been implemented. Distinguish Microsoft-authored fixtures, independent implementation agreement, library round trips, and unverified hypotheses.

- **E2 — Run Microsoft interoperability checks.** Run the existing DAO-guarded suite locally using CI-built binaries, including the engine support needed for Access 97, and check open, read, insert, update, delete and Compact & Repair. DAO120 runs through an x64 host; the current engine refuses Access97 and DAO3.6 registration is not activation evidence. Expand the successful guarded cases recorded in the validation matrix to the unverified feature variants. Missing hosts or fixtures remain explicit external dependencies; skipped DAO tests do not prove interoperability.
- **E3 — Gate integrated code on hosted CI.** Require Release builds with zero warnings/errors and both net10.0 and net8.0 test legs on CI. Only DAO tests may run locally; obtain their test runners from the matching CI revision. Run intentional fuzz jobs separately with bounded resources. Publish only `main`; temporary work branches stay local. Test the settled main revision and record the run URL, SHA and verdict. Never push upstream version tags.
- **E4 — Exercise supported operating systems.** Extend the hosted Windows/Linux/macOS matrix beyond replacement success/refusal, temporary-file cleanup and pre-canceled lock/replacement coverage. Add cross-process lock contention, cancellation during replacement and directory-durability fault coverage on each OS; same-process POSIX tests do not establish contention semantics.
- **E5 — Validate the first release workflow.** Exercise artifact handoff, package naming and publication recovery when a release is explicitly authorized. Do not add a previous-package compatibility baseline before a release exists; current targets must still expose consistent APIs.

All items belong to a workstream; independent items may run immediately without waiting for unrelated performance refactors. Dependencies follow data ownership and correctness, not the former 17-stage schedule. Every agent, including reviewers, gets a dedicated worktree. Only the integrator changes shared instructions, this list, shared docs and final CI configuration. Agents report exact completed requirements and remaining evidence gaps; the integrator reviews and lands their work on main.

## F — Real formats and encryption

- **F2 — Verify fixed-length Text across code pages and preserved schemas.** DAO establishes space padding for short fields; over-width assignments are deliberately refused rather than silently truncated. Extend native evidence beyond Jet4/ACE ASCII to Jet3, multibyte code pages, embedded NULs and malformed unassigned fields (I6). Preserve descriptor widths and storage flags through every schema edit.
- **F3 — Complete native JET/ACE encryption and password maintenance.** Native JET4 RC4 and password-only reads now have DAO-produced fixtures, and existing encrypted pages retain their key/password during updates. Implement the system-security metadata changes required for encrypt/decrypt/password changes, currently refused before mutation. Complete actual flat ACE RC4 CryptoAPI and ECMA-376 Standard providers from Microsoft-produced files and primary specifications; extend Agile beyond the native AES256-CBC/SHA512 fixture. JET3 RC4 now has a pinned upstream encrypted fixture; verify native Access97 password, mutation and compact behavior with a compatible engine. Office CFB packages and library round trips alone do not prove Access database compatibility.
- **F4 — Verify page-based Access-native Agile mutations.** A native provider now unlocks once and uses the normal page codec/pager while preserving page 0. Extend the successful native AES256-CBC/SHA512 DML/DDL/rollback and DAO write/compact cases on both targets to shrink/scrub and the other supported algorithms. Extend malformed-parameter, bounded-open and fault-sweep coverage; independent library readback alone is insufficient.
- **F6 — Stream encryption maintenance and avoid plaintext creation.** Re-encrypt flat formats page by page with atomic replacement; create encrypted databases directly. Bound memory, honor cancellation, preserve the original on failure, and handle stale temporary files without deleting another active operation's file. Verify Unix directory durability and netstandard replacement behavior; document actual guarantees. Use a coherent file-maintenance API without preserving old AccessWriter statics merely for compatibility.
- **F7 — Match Jet3 table-definition bytes.** Check 0x80 index flags, `VC` page signature/continuations, index trailers, statistics slots, descriptor bytes 7–12, and unknown page-0 bytes 0x600–0x7FF against Access 97. Preserve unknown bytes; change bootstrap hashes only with byte-level evidence. Verify Currency and decimal declarations/keys against Access 97; avoid silently narrowing a declaration Currency cannot represent.
- **F8 — Match row and long-value layout.** Verify reserved fixed-field space, fixed-only Jet3 trailers, real Jet3 jump-table boundaries, and Access record limits near 2,000/4,000. Current capacity tests prove only library round trips at 2,036/4,080 bytes. Extend native LVAL token and packing coverage beyond the verified end packing and 64-byte inline limit; verify compressed calculated Memo variants consistently for inline and spilled values. Include DAO read/compact and no-allocation-on-refusal checks.
- **F9 — Support actual collations and code pages.** Inventory supported/unsupported real database and per-column sort orders; expose explicit choices and preserve them during schema edits. Verify General 97, General Legacy and General keys, long keys, locale comparisons and uniqueness against Microsoft evidence. Repairing keys written by an old library build is not required.
- **F10 — Bootstrap standard Jet3 system objects.** New Jet3 databases lack the system rows/tables needed by `CreateRelationshipAsync`. Create the native catalog structures, preserve ownership/permissions and other metadata, and prove an Access97-compatible engine can open, enforce relationships and compact newly created databases.
- **F11 — Validate attachments and complex descriptor variants.** Obtain an Access-authored extensionless attachment; verify raw/compressed wrappers, extension lengths, empty payloads and extraction after compact. Check multi-value Decimal flags/misc bytes, calculated types, append-only metadata on real fixtures, including additional complex reference and counter variants. Compression must obey S2 resource limits.
- **F12 — Centralize verified format facts.** Consolidate per-type sizes/mappings/flags and per-format header/text/null/row layout facts under JetFormat and a type table. Characterize all 256 type codes without treating unknown codes as valid defaults. Remove scattered JetTypeInfo decisions only when equivalent fixture behavior is established; no architectural rename is a prerequisite for a data-loss fix.

## S — Hostile-file parsing and schema preservation

- **S1 — Audit every untrusted length, offset and traversal.** Header/TDEF/data/index/LVAL/usage-map/complex/CFB/XML readers must validate before allocation, slicing or arithmetic; use long offsets and checked bounds, detect cycles/shared-chain abuse, and bound depth/work by validated file geometry plus caller budgets. Reproduce truncation at each boundary, contradictory counts, oversized lengths, cyclic pointers and partial reads. Native LVAL descriptors carry 30-bit lengths; verify large real values beyond the default 16 MiB read budget and current writer emission limit. Cancellation must terminate long traversals; malformed input must not cause hangs, stack overflow or uncontrolled memory growth.
- **S2 — Bound decompression and cryptographic work.** Attachment/zlib expansion, CFB sector chains, XML descriptors, PBKDF spin counts, salts/keys and encrypted package lengths are attacker-controlled. Enforce documented configurable limits before expensive work, prohibit DTD/external entity resolution, validate declared versus actual sizes, and test bombs and invalid combinations. Add aggregate operation budgets as well as individual-value limits. Limits must distinguish supported large real files from corruption and be configurable where appropriate.
- **S3 — Complete the public decode-fault policy.** Exact MEMO/OLE readers must be wired consistently through typed, string, POCO and calculated reads. Strict reads need contextual corruption; explicitly lenient reads need a documented missing-value representation and diagnostic. Preserve unassigned raw values during writes and refuse mutation that would erase unreadable assigned content. Cover every public surface and propagate real I/O errors.
- **S4 — Complete property preservation coverage.** Extend malformed-chain refusal through all remaining property-edit/rewrite entry points and write modes. Preserve unmodeled property-entry padding, name-pool content and chunk ordering where rewrites currently normalize them. Opaque target headers and recognized native target-name lengths are modeled; verify edited output against DAO in addition to Access-authored fixture round trips.
- **S5 — Validate individual catalog rows and complex fallback discovery.** Detect malformed row contents and inconsistent object references without silently skipping them or poisoning caches. Bound flat-table fallback discovery and test strict/lenient malformed metadata explicitly. Missing required catalog structure must remain a deliberate corruption error in every mode, and filesystem I/O failures must propagate.
- **S6 — Complete linked-source access boundaries.** Ancestry/depth limits, explicit per-source credentials and device/relative/reparse-path checks now constrain linked Access reads. Bind authorization to actual opened handles to close symlink/alias races, examine physical identity and hard links, and authorize the final linked-text file. Extend refusal coverage across new execution APIs while preserving readable ODBC metadata.
- **S7 — Preserve complete schema bytes during edits.** Operate on parsed TDEF/property models while retaining unknown descriptors/chunks, sort metadata and multi-page definitions. Add/Drop/Rename must preserve surviving values/indexes/relationships and leave no temporary tables. Repro: a 202-column table with an attachment needs a multi-page transplant. Keep original descriptors through every rewrite and test real Access fixtures.
- **S8 — Verify complex schema edits with DAO.** Preserve internal reference indexes and generate them for new complex columns; confirm DAO open/compact after the complete rewrite, including multi-page TDEFs. Test NorthwindTraders ProductCategories, ComplexFields Documents and complexDataTest Table1, including TDEF@28 above live reference IDs and AppendOnly LvProp.
- **S9 — Preserve schema dependencies and application objects.** Rename/drop must handle table ValidationRule, Filter, OrderBy, lookup RowSource and saved-query dependencies with verified Access behavior, or refuse edits it cannot safely preserve. Determine Name AutoCorrect semantics. Preserve forms/reports/macros/modules/query definitions, replication/security metadata and unknown system objects byte-for-byte when unrelated data is edited; do not execute embedded code.
- **S11 — Make failures and diagnostics usable.** Give deliberate corruption, encryption, unsupported-format, size and state failures structured codes/context; preserve real I/O exceptions. Remove message matching and exception-driven valid control flow. Expose diagnostics without cell values/secrets, ignore callback failures, never invoke callbacks under I/O/pager locks, and add optional EventSource counters. No old BCL base or message must be retained solely for compatibility with this unreleased library.
- **S12 — Expand adversarial regression and fuzz coverage.** The explicit harnesses await individual inputs and the hosted workflow mutates real corpus files in processes with time/memory limits. Extend targeted mutations to counts/pointers and seek/schema/encryption paths; add coverage guidance beyond bounded random mutations. Assert no unexpected crash/hang, bounded resource use, no unauthorized links, and unchanged bytes on rejected writes. Minimize and retain reproductions; run fuzzers intentionally on hosted CI with seeds/artifacts, not as unbounded ordinary unit tests.

## I — Indexes, storage, APIs and validation

- **I2 — Maintain and reclaim index trees correctly.** Replace whole-tree rebuild/splice paths with verified B-tree insert/delete/split/merge; measure page fit instead of catching range exceptions. Preserve opaque real pages until their representation is understood (including Jet3 prefix length). Reclaim replaced trees, dropped FK leaves and empty pages without freeing shared/reachable pages; renumber cross-TDEF references when compacting descriptor slots. `PageAudit` finds 360 unreachable pages after ten extra inserts into indexTestV1997 Table1. Validate key/page/row ordering, ownership, usage maps, root growth and DAO compact. Retain the FK rebuild fallback until interoperability proves it can be removed.
- **I3 — Maintain all real usage maps.** Implement Jet3 table/index maps and column-owned/free LVAL maps. The writer omits LVAL map entries; data free-space maps remove pages only when no nonempty row or additional row slot can fit. Verify Access thresholds and deletion/reuse behavior, including Jet3. Validate INLINE-to-REFERENCE growth for owned/index/free maps against Access; allocate surgical splits through PageAllocator and undo failed reservations.
- **I4 — Recover from interrupted writes.** Add a persistent, validated, bounded rollback journal for files, covering early spills and final commits; validate identity/length/content before replay, refuse conflicts, and make recovery idempotent. Readers must see a consistent pre-crash view or refuse, never mixed pages. Consider an explicit journal stream for caller streams; state the guarantees when unavailable. Crash/fault sweeps must recover exactly before/after bytes for plaintext and real encrypted formats. Honor Access's lack of sidecar-journal awareness and verify OS durability.
- **I5 — Unify mutation validation and rollback.** Use one pipeline for row, cascade, complex, catalog and system writes; prepare/plan/validate before applying and maintain each affected index once per batch. Restore counters, allocator hints, catalog generations and caches on every rollback/failure. Extend byte-level write/flush/truncate fault sweeps to initial creation, physical shrinking and native encryption maintenance, which have separate lifecycles.
- **I6 — Update rows without lossy full rewrites.** Preserve raw unassigned fields/LVAL chains, update in place where the format allows, relocate overflow safely, and seek update/delete targets and unique keys. Non-key changes should avoid index writes; support swapped batch keys atomically. Bound memory for schema rewrites and investigate in-place DDL after preservation is proven.
- **I7 — Bound page/cache memory and establish ownership.** Add leases/pins and correct copy-on-write where beneficial; never recycle pinned/transaction pages. Unify source interfaces and invalidation, remove redundant caches/adapters only with concurrency/abandoned-scan tests and paired benchmarks. Pin counts return to zero after seeks, cancellation, LVAL traversal and concurrent scans with tiny caches.
- **I8 — Compose reads and cache catalog work.** Cache verified resolved table/index/complex descriptors, read only the selected LvProp, and invalidate writer caches on every relevant change. Use a shared scan primitive; unknown table names must be explicit errors with a separate try-lookup API. Linked Access indexes/complex reads resolve to their approved source; text links expose no indexes; ODBC execution stays explicit. Repeated metadata/count/miss/seek operations should avoid disk I/O after warmup.
- **I9 — Cache query plans and push projections safely.** Parameterize captured values without freezing mutable closures, bound shape/materializer caches, and decode only referenced columns. Use correct rounded seek bounds for integral/Currency/Decimal/Single comparisons, and ordered indexes for Min/Max when semantics permit. Profile collection Include before changing its full-child materialization. Test concurrency, eviction and changing captures.
- **I10 — Validate trimming/AOT and generated code.** Annotate generic reflection paths, isolate dynamic Include behavior, remove unsupported reflection assumptions, and build a real trimmed/AOT consumer. Verify generated consumers under trimming/AOT.
- **I11 — Measure page I/O on representative systems.** Investigate duplicate reader header reads, overlapped writer-handle cost, gated Disabled-mode concurrent scans, complex-column read-ahead, and the unexplained cold SequentialScan/first-row handoff regressions. Test Windows x64/Arm64, Linux/macOS, local disk and SMB with cancellation behavior; retain measured changes only.
- **I12 — Re-establish performance acceptance with controls.** Hosted paired typed-MEMO regressions were 5.7–13.3%, while an identical-revision control differed by 6–8%; the former 2% target is unresolved. Use repeated swapped-order/control measurements on a controlled runner. This is an acceptance requirement for relevant performance changes, not a blocker for security/correctness fixes. Preserve the evidence in read-performance-bottlenecks.md.
- **I13 — Scale relational/attachment benchmarks after write fixes.** The fixtures remain 10,000 orders and 150 attachment rows because relationship/flat-table indexes rebuild per item. Grow versioned fixtures after I2/I5, measure bounded per-item I/O and allocations, and run paired baseline/head benchmarks on GitHub Actions. Treat NA means or broken runs as failures, not evidence.
- **I14 — Document only demonstrated capabilities.** Align README/API docs with the corpus, safe-failure policy, concurrency/cache lifetime, linked-source permissions, durability, encryption provenance and target-framework differences. Separate storage preservation from execution of Access application objects. Do not advertise full JET/ACE support or malicious-input resistance as established while any required evidence above is missing.
- **I15 — Optimize mixed scalar/OLE typed scans without losing playlist definitions (MediaLibrary P2).**

MediaLibrary's `SnapshotPlaylistRow` already skips unused notes but must retain the exact `Filter` and `SortOrder` byte arrays for dynamic-playlist labels and details, including sort-only definitions. This is a typed-decoder limitation, not missing OLE support.
  - **Plan.** Add a single-scan hybrid typed plan that assigns scalar properties directly and asynchronously resolves bound OLE values through the existing exact `LongValueDecoder` reads and `LongValueReadPolicy` before yielding each target. Decode only bound columns, keep stored bytes unchanged, and do not unwrap `OleObjectValue`, extract image signatures or interpret CATraxx definitions. Dropping or deferring the definitions changes the consumer contract; a second scalar/payload scan and join is not the requested optimization. Coordinate with I7/I9 on page-buffer lifetime and projection plans, and with S1/S2/S3 on bounded traversal and decode-fault policy.
  - **Parity and failure checks.** Compare consumed metadata and exact byte arrays with the projection-aware fallback on Jet3, Jet4 and ACE and both library target frameworks. Cover null versus empty, inline/single-page/chained LVALs, overflow and deleted rows, malformed/truncated/cyclic chains, cancellation and abandoned enumeration. Preserve row order/count and real I/O failures; align strict/lenient behavior and diagnostics with S3. Keep page buffers valid across awaits, preserve the fallback for other unsupported bindings, and leave scalar-only scans fast.
  - **Performance acceptance.** Run paired baseline/head Release benchmarks on GitHub Actions with I12's swapped-order/control measurements, recording time, allocations and page I/O. Reproduce realistic sparse definitions and a 20,017-playlist workload with 4 KiB unused notes and large 4 KiB sort definitions. Compare identical retained metadata/payloads; the large case still requires roughly 78 MiB of definition bytes. Keep the current scan until the hybrid plan demonstrates a gain beyond I12's measurement noise without a large-definition regression.
